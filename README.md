## Key Architectural Principles & Features

### 1. High-Throughput Ingestion & Instant Acknowledgment
* **HTTP API Gateway & Lightweight Producer:** Intercepts incoming payment settlements, executes schema validation, and dispatches events to Amazon SQS in $< 300\text{ ms}$, immediately returning HTTP `202 Accepted` to unblock client workflows.

### 2. Strict Idempotency (Preventing Duplicate Payments)
* **Conditional Writes in DynamoDB:** Protects financial transactions against duplicate processing using atomic conditional expressions:
  $$\text{ConditionExpression} = \text{"attribute\_not\_exists}(id\_liquidacion)"$$
* **Graceful Handling:** Duplicated messages generated by SQS *at-least-once* delivery or consumer network retries catch `ConditionalCheckFailedException`, log structured warnings, and cleanly complete the message consumption cycle.

### 3. Resilience, Fault Tolerance & DLQ Sanitization
* **Dead Letter Queue (DLQ):** Messages failing business processing (e.g., negative payload values or corrupted payloads) undergo a maximum of 3 retries (`maxReceiveCount = 3`) before being isolated into `agrolink-dlq-academic`.
* **CloudWatch Alarm Integration:** Triggers automated alarms when the DLQ message count is $\ge 1$, ensuring proactive observability.

## ⚙️ Infrastructure Provisioning (Terraform)

### Prerequisites
* **Terraform** $\ge 1.3.0$
* **AWS CLI** configured with appropriate IAM permissions
* **Node.js** $\ge 18.x$

### Deployment Steps

1. **Clone the Repository:**
   ```bash
   git clone https://github.com/AlexanderS1977Sanchez/Liquidaci-n-as-ncrona-AWS.git
   cd AgroLink-Andes/terraform
   ```

2. **Initialize Environment Variables:**
   ```bash
   cp terraform.tfvars.example terraform.tfvars
   ```

3. **Initialize Terraform & Remote Backend:**
   ```bash
   terraform init
   ```

4. **Review & Apply Infrastructure:**
   ```bash
   terraform plan -lock=false
   terraform apply -auto-approve
   ```
5. **Review**
   ```bash
   terraform destroy
   ```

## 🔒 Security & IAM Governance

* **Least Privilege Access:** Producer and Consumer Lambda functions operate on distinct IAM roles (`iam_producer_role` and `iam_consumer_role`) with granular permissions scoped exclusively to required ARNs.
* **Encrypted Storage:** Terraform state files are encrypted at rest using Amazon S3 server-side encryption with strict DynamoDB table locking.
